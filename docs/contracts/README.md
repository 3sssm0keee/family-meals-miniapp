# 家庭点饭系统前后端开发契约 V1.0

本目录是供 Codex 后端与 Gemini 小程序前端共同使用的完整 V1 契约包。替代上层目录的“前后端关键关系设计-v0.1.md”提纲。旧文件保留作设计历史，不继续作为接口实施依据。

完成范围：43 个接口操作、49 个数据结构、请求与成功/错误响应、参数限制、权限、幂等、状态流转、数据库字段与索引、前端交接、样例及40个联合验收场景。

| 文件 | 用途 |
| --- | --- |
| openapi-v1.json | OpenAPI 3.1 主契约，可导入支持该版本的API工具 |
| 接口索引-v1.md | 按路径与operationId快速定位 |
| 业务规则与数据字典-v1.md | 业务默认、权限、事务、计量、状态及数据库字段 |
| Gemini前端交接-v1.md | 前端开发范围、页面对应接口、异常与交付要求 |
| frontend-types.ts | 从契约自动生成的TypeScript数据与操作类型 |
| examples-v1.json | 逐接口输入/输出样例，含完整人数去重审核例子 |
| 验收场景-v1.md | 40个待真实系统执行的验收场景 |
| validation-report.json | 本轮离线契约检查结果及文件SHA-256 |
| build_contract.py / check_contract.py | 标准库生成与检查脚本 |

建议先让前端开发者阅读 Gemini前端交接-v1.md，再导入 OpenAPI 和类型。两端使用相同版本，API不得私自增删字段。前端开发者不需要运行数据库或读取任何服务端密钥。

当前没有真实后端地址、测试账号或微信消息模板；这些属于后续环境交付，不应在文档中编造。现在可以按契约开发页面和API封装；真实联调在后端就绪后进行。

## 再生成与验证

在仓库根目录分别运行：

```powershell
python docs/contracts/build_contract.py
python docs/contracts/check_contract.py
```

检查覆盖：所有内部schema引用、路径参数、operationId唯一性、管理权限标签、必填幂等头、每接口样例参数/正文/响应、10个非法输入、3/2/4去重展示和公共视图不含名单。

校验脚本覆盖本契约实际使用的JSON Schema关键字，不是完整第三方OpenAPI验证器；本机未找到该验证器及TypeScript编译器，未宣称通过这些检查。业务场景、MySQL事务、微信实际显示和消息送达均未执行。本交付是完整设计契约，不是已实现系统。

本版未逐项由用户确认的默认规则已集中列明，包括每餐一次提交、制作份数允许一位小数、访客不自动到期等。其目的在于消除开发歧义；若用户改变这些规则，先同步契约再改实现。
